# Karaoke Platform 0.9.0

The headline of this release is the **AI Karaoke DJ**: the library is now
addressable by AI agents over the Model Context Protocol, and the DJ booth it
powers builds a live setlist that syncs to YouTube Music.

## AI DJ Booth and the `dj-list` setlist

- **DJ Booth in the TUI (`D`)**: An interactive chat booth over the 18,000+
  track library. Suggests harmonically compatible follow-ups using the Camelot
  wheel and BPM matching, with numbered one-click queueing (`1`..`4`,
  `/queue all`) so a set can be built without touching raw track IDs. Runs
  against local Ollama with a deterministic library-tool fallback when the LLM
  is offline. Also available standalone as `karaoke-dj`.
- **Persistent setlist synced to YouTube Music**: Tracks queued by the DJ land
  in the canonical `dj-list` playlist in PostgreSQL and are mirrored to a real
  YouTube Music playlist, resolved or created on demand. The TUI reconciles
  local and remote state when the playlist view opens, matching remote tracks
  back to the library by artist and title when video IDs do not line up.
- **The set never repeats itself**: Suggestions exclude songs already in the
  setlist, so working through `/suggest` keeps producing fresh material instead
  of re-offering what was just queued. Adding a song twice is a no-op that
  reports `already_present`, short-circuiting before the YouTube Music call.
- **Lyric Vibe (`v`)**: Mood arc, sentiment breakdown, and vocal delivery tips
  for the playing track, fetching and caching synced lyrics from LRCLIB on
  demand when the library has none.

## MCP server

- **Nine tools over MCP**: `search_songs`, `get_now_playing`,
  `suggest_next_tracks`, `analyze_lyric_vibe`, `get_dj_stats`, `play_track`,
  plus `add_to_dj_playlist`, `get_dj_playlist` and `clear_dj_playlist`. Any MCP
  client — Claude Code, Claude Desktop — can now search the library by key,
  Camelot code, BPM and genre, read what is playing, and drive playback.
- **Two transports on one port**: The server speaks both legacy SSE and
  Streamable HTTP on `/sse` (aliased at `/mcp`), dispatching on method and
  `Accept`. Clients disagree about which to use — Claude Code opens an event
  stream, Obot posts JSON-RPC — and serving only SSE answered those POSTs with
  405. Adds `/health` and `/` status endpoints.
- **Obot gateway integration**: Obot rejects MCP server URLs that resolve to a
  private IP, so the gateway reaches the library through an `obot tunnel`
  process holding an authenticated outbound connection, scoped to
  `http://127.0.0.1:8888/*` alone.

## Fixes

- **`play_track` never worked over MCP**: it called `open_song_url()` without
  its required `kind` argument, raising `TypeError` on every invocation. It now
  also forwards artist and title, which is what lets YouTube Music resolve the
  canonical audio track rather than a video edit carrying a different intro.
- **`play_track` reported success as failure**: status was derived from the
  return value's truthiness, but a pid comes back only from the `xdg-open`
  path — the kiosk/CDP path returns `None` on success, as do the refusal paths.
  Status is now `launched` with the pid surfaced separately.
- **Now-playing and search matching**: both fall back to relaxed
  artist/title matching and URL lookup, so a track whose player metadata does
  not exactly match the library still resolves.

## Deployment

- `karaoke-mcp.service` and `karaoke-obot-tunnel.service` ship as systemd
  `--user` units bound to `karaoke.target`, symlinked from the repo like the
  rest of the stack. The tunnel `Wants` rather than `Requires` the MCP server,
  so restarting the server does not drop the gateway connection.
- New console scripts: `karaoke-mcp` and `karaoke-dj`.
